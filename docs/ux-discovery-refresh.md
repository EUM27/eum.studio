# 기능 발견성과 보조 작업면 개선

2026-09-08. 원고 중심 화면을 유지하면서, 숨겨진 기능의 진입점과 보조 화면의 사용성을 정리한다.

## 현재 화면에서 확인한 문제

| 흐름 | 확인한 문제 | 반영한 동작 |
|---|---|---|
| 집필 중 기능 찾기 | 사이드바의 빠른 전환이 숨겨지고, 검색에는 작품·회차와 두 명령만 나온다. | 상단 `도구 찾기`와 Ctrl+K에서 기존 기능을 이름·설명·관련어로 검색한다. 목적별 분류와 각 기능의 설명을 제공한다. |
| 홈에서 작업 도구 열기 | 작품을 먼저 열고 기능 위치를 찾아야 한다. | 현재 작품의 도구를 고르면 유지 중인 작업공간을 표시하고 그 도구를 연다. 작품·회차를 다시 선택하거나 원고를 다시 만들지 않는다. |
| 작업면 이동 | 다섯 메뉴에 네 열이 지정되어 운영 메뉴가 다음 줄로 밀린다. | 메뉴 수에 따라 열을 배치한다. 구조·검토의 하위 화면에는 사용 목적을 설명한다. |
| 구조·기록 | 작업면으로 옮겨진 콘텐츠의 스타일이 팝업에만 적용되고 일부 입력이 가로로 넘친다. | 내장 작업면의 폼·요약·목록·카드를 직접 스타일링하고 내용과 가용 폭에 맞춰 열을 배치한다. |
| 파편 서랍 | 도구 막대가 큰 빈 공간을 차지하고 선택이 없을 때 다음 행동이 불분명하다. | 헤더·도구·안내·목록을 분리하고 `원고에서 선택하기`를 제공한다. |
| 원고 점검·설정 | 체크박스가 넓은 입력 상자처럼 표시된다. 설정 항목은 긴 한 목록으로 이어진다. | 체크 요소의 표시를 바로잡고 설정을 집필 기준·조수와 장면 분석·음악으로 분류한다. 탭을 옮겨도 입력 중인 값은 유지한다. |
| 주석 | 선택하지 않은 상태에서 전체 입력 폼이 검토 레일을 차지한다. | 선택 전에는 사용 안내를 표시하고, 선택하거나 작성 중인 주석이 있으면 폼을 표시한다. |
| 별빛·작품의 빈 상태 | 빈 목록만 보여 기능을 시작하는 경로가 불명확하다. | 인물·별빛 추가와 첫 작품 생성·기존 데이터 가져오기를 직접 연결한다. |
| 운영 | 설명 없는 큰 빈 타일이 화면 대부분을 차지한다. | 투고·계약·정산의 목적과 열기 동작을 내용 크기의 카드로 표시한다. |
| 운영 입력 | 중첩된 입력 그룹이 반쪽 열에 들어가고 선택한 탭의 표시가 맞지 않는다. | 입력 그룹에 가용 폭을 배분하고 실제 선택 상태에 강조를 적용한다. |

## 구현 경계

- 도구 정의와 콜백은 renderer의 `StudioToolRegistry`에 등록한다. 검색할 때만 표시 정보를 사용하며, 실행할 때는 최신 콜백과 사용 가능 여부를 다시 확인한다. 콜백만 바뀌면 셸을 다시 그리지 않는다.
- 작품 도구는 기존 controller와 navigation을 호출한다. DOM 버튼을 대신 누르거나 새로운 저장 경로·도메인 원본을 만들지 않는다.
- 선택한 원고의 범위, 문서별 실행취소·다시실행, 저장과 재시작 복원은 기존 계약을 사용한다.
- 기존 테마 변수를 사용한다. 새 의존성, 제공자 기본값, 데이터 migration은 없다.
- 기본 설치본과 실사용 데이터의 교체는 이 변경의 자동 작업에 포함하지 않는다. 화면 점검과 패키지 검증은 별도 작업공간에서 실행한다.

## 검증

- `npm run check`: 프로젝트의 정적·단위·통합 검사와 production build.
- `npm run architecture:check`: domain·application·platform·renderer의 의존성 경계.
- `npx playwright test tests/e2e/tool-discovery.spec.ts`: 도구 검색과 실제 실행, 정확한 선택 원문 복사, 원고 보존, 홈에서 작업 도구 이동, 설정 탭의 입력 유지, 키보드 포커스 복원, 완전 재시작.
- 기존 빠른 메모, 설정 저장, 작업면 이동, 도구 팝업 배치, 음악 바, 어두운 테마 시나리오를 관련 회귀로 확인한다.
- 시각 점검에서는 실제 Electron 화면을 캡처하고 같은 화면 크기에서 비교한다. 스크린리더 전체 인증이나 외부 제공자 기능의 품질을 화면 검사만으로 주장하지 않는다.

실행 결과와 화면 캡처는 `artifacts/`의 해당 실행 폴더에 보관한다. 이전 통과 기록은 현재 실행을 대체하지 않는다.
