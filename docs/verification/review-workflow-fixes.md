# 작업 흐름 검토 수정

2026-09-08 전체 프로젝트 검토에서 재현한 문제를 수정한다. 기본 설치본 승격과 실사용 데이터 변경은 이 작업에 포함하지 않는다.

## 저장과 기록

- mutation을 enqueue할 때 선행 save promise를 고정해 callback에 전달한다. 이후 enqueue된 transfer가 자신보다 앞선 mutation의 대기 대상이 되는 순환을 막는다.
- 회차 이동은 두 작업 큐를 함께 막고, 이동 이후의 저장·변경은 이동이 끝난 뒤 실행한다. 실패한 호출 뒤 다음 호출이 진행되는 계약을 유지한다.
- 실제 런타임 회귀는 제목 변경 두 건과 원고 이동을 함께 요청하고, 양쪽 본문과 이동 실행 취소 결과를 확인한다.
- 활동 기록의 글자 변화량은 불변 DocumentRevision의 UTF-16 길이에서 계산한다. 한 조회 안에서 같은 revision metadata를 재사용하며 원고 blob을 다시 읽지 않는다.

## 작품과 연결 수명

- 셸에 보관한 작품 설정은 현재 workId와 일치할 때만 전달한다. 다른 작품에서는 자동 분석 컨트롤러가 해당 작품 설정을 조회한다.
- 수동 이야기 흐름 생성·재생성·권한 재시도는 작품 전환 세대와 요청 토큰을 확인한다. 대기 권한의 작품과 대화 identity를 유지하고, 전환 뒤 늦은 결과·오류·재시도를 반영하지 않는다.
- 메일 연결 변경 세대를 확인하고 연결 게시 작업을 직렬화한다. 동기화 응답은 현재 연결 identity도 확인하여 연결 해제 완료 뒤 이전 자격 증명을 다시 저장하지 않는다.
- 여러 설정 저장의 부분 성공은 각각의 결과와 revision을 반영한다. 실패한 항목을 고친 뒤 같은 화면에서 재시도할 수 있다.

## 미디어와 패키지

- 등록 checksum이 있는 미디어는 main 재생 경로에서 무결성을 검증한다. descriptor, 파일 identity, 크기, 수정·변경 시각이 같은 요청은 완료된 검증을 공유한다. 변경·재연결·실패 시 이전 검증을 적용하지 않는다.
- Windows 패키징은 고유 후보를 기본으로 만들고, 명시한 경로라도 기존 항목을 덮어쓰거나 삭제하지 않는다. 검증 대상 이름은 호출자가 명시한다.
- 복구 경로 거부 사례를 개별 테스트로 분리해 여러 PowerShell 시작 시간을 하나의 기본 제한 시간 안에 합산하지 않는다.
- 정적 CSS 검사는 읽은 코드의 CRLF/LF 차이만 정규화한다. 실제 선택자·속성·cascade 순서 검증은 그대로 유지해 Windows 체크아웃에서도 같은 검사를 실행한다.

## 검증 명령

일반 필수 검증과 별도 Windows 후보 검증은 [검증 절차](../verification.md)의 core와 heavy를 따른다. 원고 이동·수명·설정·미디어·패키지의 단위 회귀는 전체 Vitest 검사에 포함된다.

```powershell
npm run verification:core
npm run verification:heavy -- --process-budget-ms 1800000
npx playwright test tests/e2e/review-lifecycle.spec.ts
```

추가 Electron 시나리오는 현재 작품의 자동 분석 설정, 부분 저장 뒤 올바른 revision 재시도, 작품 전환 뒤 수동 요약의 늦은 권한 응답, 변경된 미디어의 실제 protocol 거부를 검증한다. 외부 연결 실패·지연만 테스트가 만든 격리 입력으로 대체하며 실제 계정에 요청하지 않는다.

실행 결과는 각 실행의 검증 JSON과 로그로 확인한다. 커밋 직전 검증에는 커밋에 포함될 파일만 담은 별도 checkout을 사용하며, 관련 없는 기존 미커밋 파일과 스테이징된 복구 자료 삭제는 보존한다.
